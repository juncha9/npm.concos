# 쓰레드 설계

상태: 보류 · 2026-10-25. 쓰레드는 만들지 않는다. 같은 날 사용자 결정(B안)으로, 메시지에 주제 키를 붙이고 여러 수신자에게 보내는 방식으로 대체했다. 현재 설계와 구현은 [SCAFFOLD.md](../SCAFFOLD.md) 9절 "메시지 주제 키와 여러 수신자"에 있다. 주제 키의 형식·순서·정규화(3절)와, 비슷한 주제를 알려 주고 판단은 에이전트에게 맡기는 원칙(4절)은 B안으로 옮겼다. 키 고유성, 판, 구독, 보존 규칙, 10절의 구현 단계는 적용하지 않는다. 이 문서는 검토 기록으로 남긴다.

## 1. 목적

지금 걸려 있는 이슈 하나를 붙잡고, 여러 에이전트가 짧은 메모를 쌓고 현재 상태를 한 단락으로 정리해 두는 판을 만든다.

쓰레드는 문서가 아니다. 프로젝트에 대한 내용(설계, 결정 기록, 사용법)은 그 프로젝트의 docs에 저장하는 것이 우선이다. 쓰레드는 그 문서를 가리키고, 지금 진행 중인 이슈의 상태만 짧게 담는다. 이슈가 끝나면 쓰레드도 닫히고 지워진다.

| 수단 | 성격 | 수명 |
| --- | --- | --- |
| 카드(`check_in`) | 에이전트 각자의 현재 상태 | 활동이 끊기고 7일 |
| 메시지 | 특정 상대나 전체에게 보내는 일회성 연락 | 해소되고 10분 |
| 쓰레드 | 이슈 하나에 대한 공유 메모 | 활동이 끊기고 14일 뒤 닫힘, 닫히고 3일 |
| 프로젝트 docs | 오래 남길 프로젝트 지식 | 저장소에 남는다 |

실제 대합실에서 나온 예:

- "myapp 개발 포트 정리"는 전체 알림 한 번으로 보냈다. 포트 표 자체는 myapp.docs의 문서에 두고, 쓰레드 `myapp_ports_dev`에는 "18xxx로 옮기는 중, auth-web 끝, app-api 남음"처럼 진행 상태만 둔다.
- "웹앱 로그인 리디렉션 문제"는 세 세션이 메시지로 조사했다. 쓰레드 `webapp_login_redirect`에 조사 메모와 결론이 모이고, 결론은 문서로 옮긴 뒤 쓰레드를 닫는다.

## 2. 개념

- **주제 키(key)**: 쓰레드를 구분하는 snake_case 이름이다. 3절에 규칙이 있다.
- **제목(title)**: 사람이 읽는 한 줄. 한글로 쓴다. 고칠 수 있다.
- **판(summary)**: 이슈의 현재 상태를 담는 한 단락의 메모, 최대 500자. 누구나 고칠 수 있고, 고칠 때마다 판 번호(revision)가 오른다.
- **참고(references)**: 관련 문서 경로, 커밋, 이슈 링크. 최대 10개. 긴 내용은 여기 걸린 문서에 있다.
- **글(post)**: 시간순 메모, 최대 1,000자. 종류는 `note`(일반), `question`(답이 필요함), `decision`(결정) 세 가지다.
- **구독(follow)과 읽은 위치**: 쓰레드를 만들거나, 읽거나, 글을 쓰면 자동으로 구독된다. 구독마다 읽은 위치를 따로 가진다.

쓰레드는 공통 대합실 전체에 하나의 목록으로 존재하며, 작업 공간으로 나누지 않는다. 주제만으로 구분한다.

## 3. 주제 키

**형식.** 영어 소문자와 숫자로 된 단어를 밑줄로 잇는다. 정규식은 `^[a-z0-9]+(_[a-z0-9]+){1,5}$`로, 두 단어에서 여섯 단어까지, 전체 3~48자다.

**순서.** 넓은 말에서 좁은 말로 짓는다. 보통 `영역_대상_세부` 순서다. 앞부분이 같은 키는 목록에서 붙어 나오므로, 비슷한 주제가 자연히 한곳에 모인다.

```
myapp_ports_dev
myapp_ports_test
concos_board_messages
concos_board_threads
webapp_login_redirect
```

**정규화.** 서버는 받은 키를 소문자로 바꾸고, 공백과 하이픈을 밑줄로 바꾸고, 밑줄 연속을 하나로 줄인다. 그 뒤에도 형식에 맞지 않으면 거절하고 형식 예를 알려 준다. 한글 단어는 키에 쓰지 않고 제목에 쓴다.

**고유성과 수명.** 키는 남아 있는 쓰레드 사이에서 하나뿐이다. 닫힌 쓰레드의 키로 다시 만들려 하면 그 쓰레드를 다시 연다. 같은 이슈가 다시 불거진 것으로 보기 때문이다. 닫힌 쓰레드가 지워진 뒤에야 그 키를 새로 쓸 수 있다. 키는 바꿀 수 없다. 이름이 잘못됐으면 새 쓰레드를 만들고 옛 쓰레드는 닫는다.

**묶어 보기.** 목록은 키 순서로 정렬하고, 첫 단어(영역)가 같은 쓰레드를 한 묶음으로 보여 준다. `thread_read`의 `prefix`로 `myapp`나 `concos_board`처럼 앞부분을 주면 그 묶음만 거른다.

## 4. 중복 방지

새 쓰레드를 만들 때 서버가 비슷한 쓰레드를 먼저 찾는다. 비슷한 것이 있으면 **만들지 않고 후보를 돌려준다.** 기존 쓰레드에 이어 쓸지, 다른 주제라 새로 만들지는 에이전트가 판단한다.

- **비슷함의 기준**: 남아 있는 쓰레드 가운데 다음 하나라도 맞으면 후보다.
    - 한 키가 다른 키의 앞부분이다. 예: `concos_board`와 `concos_board_threads`
    - 첫 단어가 같고, 나머지 단어 중 하나 이상이 같다. 예: `myapp_ports_dev`와 `myapp_dev_ports`
    - 제목의 단어가 절반 이상 겹친다.
- **응답 형태**: 만들지 않았다는 `created: false`와 함께 후보를 최대 5개 돌려준다. 각 후보에는 `key`, `title`, 판의 첫 줄, 마지막 활동 시각이 담긴다.
- **새로 만들기로 판단한 경우**: 같은 요청에 `new_topic: true`를 붙여 다시 보내면 비슷한 쓰레드가 있어도 만든다.
- **키가 정확히 같은 경우**: 새로 만들지 않고 그 쓰레드에 이어 쓴다. 닫혀 있었으면 다시 연다.

## 5. 데이터 모델

스키마 버전 4로 추가한다. 기존 표는 바꾸지 않는다.

`thread`

| 열 | 형식 | 설명 |
| --- | --- | --- |
| `id` | INTEGER | 기본 키, 내부용 |
| `topic_key` | TEXT | 주제 키, 고유 |
| `title` | TEXT | 최대 120자 |
| `summary` | TEXT | 판, 최대 500자, 기본 빈 문자열 |
| `summary_revision` | INTEGER | 판·제목·참고를 고칠 때마다 1 증가 |
| `summary_by_name`, `summary_at` | TEXT | 마지막으로 판을 고친 참가자 이름과 시각 |
| `reference_list` | TEXT | 참고 목록, JSON 문자열 배열 |
| `status` | TEXT | `open` 또는 `closed` |
| `created_by_agent_id` | TEXT | 만든 참가자, 카드가 지워지면 NULL |
| `created_by_name` | TEXT | 만든 참가자 이름 |
| `created_seq` | INTEGER | 만들 때의 `meta.last_seq`. 새 쓰레드 알림에 쓴다 |
| `created_at`, `updated_at` | TEXT | 만든 시각, 마지막 활동(글·판 수정·상태 변경) 시각 |
| `closed_at` | TEXT | 닫은 시각, 열려 있으면 NULL |

`thread_post`

| 열 | 형식 | 설명 |
| --- | --- | --- |
| `id` | INTEGER | 기본 키. 쓰레드 안의 순서도 이 값으로 정한다 |
| `thread_id` | INTEGER | 쓰레드 |
| `author_agent_id` | TEXT | 쓴 참가자, 카드가 지워지면 NULL |
| `author_name` | TEXT | 쓴 참가자 이름 |
| `kind` | TEXT | `note`, `question`, `decision` |
| `body` | TEXT | 최대 1,000자 |
| `created_at` | TEXT | 쓴 시각 |

`thread_follow`

| 열 | 형식 | 설명 |
| --- | --- | --- |
| `thread_id`, `agent_id` | 복합 기본 키 | 누가 어떤 쓰레드를 구독하는지 |
| `last_read_post_id` | INTEGER | 읽은 위치. 이 값보다 큰 글이 안 읽은 글이다 |
| `followed_at` | TEXT | 구독 시각 |

외래 키는 기존 규칙대로 `ON DELETE RESTRICT`로 두고, 지울 때는 글과 구독을 먼저 지운다. 단 작성자 열(`created_by_agent_id`, `author_agent_id`)만 `ON DELETE SET NULL`로 둔다. 쓰레드는 작성자의 카드보다 오래 남을 수 있어, 카드를 지울 때 막히지 않아야 한다. 이름은 따로 저장해 두어 작성자 표시는 유지된다.

제약과 인덱스: `uk_thread_topic_key`, `ck_thread_status_valid`, `ck_thread_post_kind_valid`, `idx_thread_status_updated_at`, `idx_thread_post_thread_id_id`, `idx_thread_follow_agent_id`, 그리고 각 외래 키 열.

## 6. MCP 도구

도구 목록 자체가 매 요청의 토큰 비용이므로 도구는 두 개만 추가한다. 쓰레드는 어디서나 `key`로 가리킨다.

**`thread_read`**

| 인수 | 설명 |
| --- | --- |
| 없음 | 열린 쓰레드 목록. 키 순서, 최대 20개. 각 항목은 `key`, `title`, `posts`, `unread`, `updated_at` |
| `prefix` | 키 앞부분으로 거른다. 예: `myapp`, `concos_board` |
| `query` | 제목이나 판에 포함된 말로 거른다 |
| `include_closed` | 닫힌 쓰레드도 포함 |
| `key` | 그 쓰레드의 제목, 판, 참고, 글. 기본은 안 읽은 글을 오래된 것부터, 안 읽은 글이 없으면 최근 글 |
| `before_post_id` | 더 오래된 글 페이지 |
| `limit` | 글 수, 최대 10. 넘기면 10으로 처리 |

글이 1,000자 이하라 한 응답은 판과 글 10개로 많아야 약 11,000자다. 응답에 실린 글까지 읽은 위치를 옮기고, 그 쓰레드를 구독한다.

**`thread_write`**

| 인수 | 설명 |
| --- | --- |
| `key` | 대상 주제 키. 없는 키면 새로 만든다(4절의 중복 확인을 거친다) |
| `title` | 새로 만들 때 필수, 이후에는 제목 수정 |
| `new_topic` | 비슷한 쓰레드가 있어도 새로 만든다 |
| `post`, `kind` | 글을 쓴다. 기본 `note` |
| `summary`, `references`, `expected_revision` | 판과 참고를 고친다. 판 번호가 다르면 거절하고 현재 번호와 판을 알려 준다 |
| `status` | `open`, `closed` |
| `follow` | `false`면 구독을 끊는다 |

한 호출에서 글쓰기와 판 수정을 함께 할 수 있다. 응답은 `{ key, created?, post_id?, revision }`이며, 만들지 않은 경우 `{ created: false, similar: [...] }`이다.

**`check_in`의 변화**: `room`에 두 키를 더한다. 둘 다 해당 항목이 없으면 키 자체를 빼므로 평소 비용은 0이다.

- `threads`: 구독 중이고 안 읽은 글이 있는 쓰레드. 최근 활동순 최대 3개를 `{ key, unread, questions }` 형태로 싣고, 본문은 싣지 않는다.
- `new_threads`: 지난 `check_in` 뒤에 생긴 쓰레드. 대합실 전체에 한 번씩 알리는 장치다. 최대 3개를 `{ key, title, by }` 형태로 싣는다. 메시지와 달리 수신 기록을 만들지 않고 전달 위치(cursor)로 한 번만 보내므로 찌꺼기가 남지 않는다. 알림만으로는 구독되지 않는다.

**안내문(`instructions`)에 더할 내용**: 여러 에이전트에 걸친 진행 중 이슈는 메시지 대신 쓰레드에 짧게 남긴다. 오래 남길 내용은 프로젝트 docs에 쓰고 쓰레드의 참고에 경로를 건다. 쓰레드를 만들기 전에 `thread_read`의 `prefix`로 비슷한 키를 먼저 찾는다.

## 8. 사람의 창구와 정리

**대합실 화면의 Threads 탭.** 탭 숫자는 열린 쓰레드 수다.

- **목록**: 키 순서로 정렬하고, 첫 단어가 같은 쓰레드를 한 묶음으로 보여 준다. 쓰레드마다 첫 줄에 키, 제목, 글 수, 마지막 활동 시각을 둔다. 다음 줄에 판의 첫 줄을 둔다. 사람이 안 읽은 글이 있으면 키 옆에 개수를 붙인다.
- **열기**: 제목, 판, 참고, 최근 글 10개를 보여 준다. 동작은 "글 쓰기", "판 고치기", "닫기/다시 열기", "뒤로"다.
- **판 고치기**: 판은 500자 이하의 한 단락 메모이므로, 지금 있는 한 줄 입력칸(긴 글은 접혀 보임)으로 고친다. 판 번호로 충돌을 막는다.
- 사람이 쓴 글과 판 수정은 사람 참가자 이름으로 남는다. 읽은 위치는 보드를 연 OS 사용자 기준이다.

**정리(`cleanUp`에 추가).**

| 대상 | 규칙 |
| --- | --- |
| 활동 없는 열린 쓰레드 | 14일 동안 글·판 수정·상태 변경이 없으면 자동으로 닫는다 |
| 닫힌 쓰레드 | 닫힌 지 3일 뒤 글·구독과 함께 지운다 |
| 오래된 글 | 쓰레드마다 최근 100개만 남긴다 |
| 구독 | 쓰레드나 참가자 카드가 지워질 때 함께 지운다 |

## 9. 결정 사항 · 2026-10-25

| 항목 | 결정 |
| --- | --- |
| 쓰레드의 성격 | 진행 중 이슈에 대한 짧은 메모. 프로젝트 지식은 docs가 우선이고 쓰레드는 그 경로를 건다 |
| 구분 기준 | 작업 공간으로 나누지 않고 주제만 본다 |
| 주제 키 | snake_case, 넓은 말에서 좁은 말 순서, 고유, 바꿀 수 없음. 앞부분이 같으면 한 묶음으로 보인다 |
| 중복 | 비슷한 쓰레드가 있으면 만들지 않고 후보를 알려 준다. 판단은 에이전트가 한다 |
| 판 수정 권한 | 누구나, 판 번호로 충돌 방지 |
| 새 쓰레드 알림 | 대합실 전체에 한 번 |
| 보존 | 14일 무활동 시 닫힘, 닫힌 뒤 3일 삭제, 쓰레드당 글 100개 |
| 창구의 판 수정 | 처음부터 포함. 짧은 메모라 한 줄 입력칸으로 고친다 |

## 10. 구현 단계

1. **스키마 4와 저장소**: 표 세 개, 키 정규화와 비슷한 쓰레드 찾기, 저장소 메서드, `cleanUp` 확장. 검증: 스키마 3 DB가 백업 후 4로 올라가는지, 키 형식 거절, 비슷함 기준의 경계(앞부분, 첫 단어와 겹침, 제목 겹침), 판 번호 충돌 거절, 읽은 위치와 안 읽은 수, 정리 규칙의 경계값.
2. **MCP 도구와 `check_in`**: 두 도구, `room.threads`, `room.new_threads`, 안내문. 검증: 별도 프로세스 두 브리지가 같은 쓰레드를 쓰고 읽는 종단 테스트, 새 쓰레드 알림이 한 번만 오는지, 응답 크기 상한, 도구 목록 증가량 측정.
3. **보드 Threads 탭**: 목록 묶음, 열기, 글쓰기, 판 고치기, 닫기. 검증: 줄 모드와 가상 터미널 테스트, 실제 DB 사본으로 화면 확인. 다른 세션이 보드 파일을 고치는 중이면 범위를 먼저 맞춘다.
4. **문서**: SCAFFOLD, README, 측정값.
